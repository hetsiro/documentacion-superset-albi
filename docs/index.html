4Actualización de datos (ETL)

  • Scripts: SQL/CentinelaDashboards Prod-HubIntegracion.sql y SQL/CentinelaAsistencia Prod-HubIntegracion.sql.
  • Cada corrida hace TRUNCATE + INSERT completo (últimos 6 meses).
  • El INSERT no lleva lista de columnas: el orden del SELECT debe calzar 1:1 con el orden físico de la tabla.

5Agregar o quitar columnas

  1. Agregar el LEFT JOIN (si aplica) y la columna al final del SELECT, en ambos bloques del script (PASO 1 crear tabla y PASO 2 insert).
  2. Ejecutar el ALTER TABLE antes de la próxima corrida del ETL (si no, el INSERT posicional falla): 
    ALTER TABLE HubIntegracion.albi.CentinelaDashboards ADD NuevaColumna INT NULL;
  3. Refrescar la vista (cachea la lista de columnas del SELECT *): 
    EXEC sp_refreshview 'albi.v_OrdenesTrabajoCentinela';
  4. En Superset: Dataset → Sync columns from source (y marcar Is temporal si es fecha).
  5. Diccionario: agregar la columna a docs/data/cols_meta_centinela.js y correr scripts/generar_lookup_centinela.bat.
⚠️ La columna nueva siempre al final (el ALTER la deja al final; el SELECT debe ponerla al final). Si se intercala, los datos se cruzan de columna. Para cambios estructurales grandes: DROP TABLE, correr el ETL (recrea la tabla) y re-sincronizar el dataset.

6Actualizar dashboards por ZIP

🐛 Bug de Superset 6.1.0 (#34879): importar un dashboard existente no actualiza los charts ni datasets que ya existen, aunque se confirme el overwrite. Corregido recién para la 7.0.

Flujo que sí funciona para actualizar vía ZIP:

  1. Eliminar el dashboard.
  2. En Charts, filtrar por «Centinela» y eliminar en bloque los charts del dashboard (ojo con los que no llevan prefijo).
  3. No tocar los datasets.
  4. Importar el ZIP: los charts se recrean desde el export.

Si solo cambió el layout del dashboard (no los charts), basta importar con overwrite.

7Clonar un dashboard para otro cliente

  1. Exportar el dashboard original (⋯ → Export).
  2. En los YAML: reemplazar prefijos ([Ameco] → [Cliente]) y nombres de datasets/tablas.
  3. Generar UUIDs nuevos para todos los charts y el dashboard (si no, sobrescribe el original).
  4. Conservar los UUIDs de datasets y base de datos = los reales del destino en Superset (verlos vía API /api/v1/dataset/ y /api/v1/database/); renombrar carpeta datasets/<BD>/ y archivo databases/<BD>.yaml al nombre destino.
  5. Crear el ZIP con rutas forward slash (desde Git Bash: tar.exe --format zip, o dentro del contenedor con Python). Un ZIP hecho con PowerShell falla silenciosamente.

8Deploy de la imagen

# build y push (requiere docker login acrsuper1284.azurecr.io)
docker build -f Dockerfile.prod -t acrsuper1284.azurecr.io/superset-mssql:6.1.0 .
docker push acrsuper1284.azurecr.io/superset-mssql:6.1.0

  2. Pestaña Conectar → /bin/bash → ejecutar superset db upgrade && superset init.

Preferir tags de versión explícitos antes que :latest, para poder volver atrás.

9Problemas conocidos

SíntomaCausaQué hacer
Importo un ZIP y los charts no cambian Bug import 6.1.0 (#34879) Borrar dashboard y charts, luego importar (sección 6)
Cambio un filtro del dashboard y sigue mostrando el anterior Superset guarda la selección de filtros por usuario 90 días (native_filters_key en la URL) Abrir la URL limpia (sin native_filters_key), usar «limpiar filtros», o incógnito
Roles se ven como números Regresión de la UI de seguridad (React) en 6.x Ver nombres en Settings → List Roles o API /api/v1/security/roles/
Datos «viejos» tras correr el ETL En prod no hay caché de datos (NullCache) — suele ser el estado de filtros o el ETL aún no corre Verificar «Last queried at» del chart; forzar refresh

11Actualizar la doc de cálculos

La página Cálculos de los charts se genera automáticamente leyendo los charts en vivo desde la API de Superset. Cada vez que cambies una métrica o un filtro, vuelve a generarla:

  • Doble clic en scripts\Actualizar-calculos-charts.bat — abre una ventana, muestra el progreso y queda abierta al terminar.
  • O desde consola: node scripts/calculos_fetch.js
⚠️ No necesita dashboards exportados (no usa la carpeta exports/): lee la API directamente. Requisitos: Node.js instalado y acceso a reporting.boe-hub.com. Tampoco edites el HTML a mano — se sobrescribe.

Qué hace: entra a la API, baja los charts de los 4 dashboards (IDs 37/38 Centinela, 23/24 Ameco), extrae métrica, filtros, columna de fecha y dimensiones de cada uno, y regenera el HTML. Es de solo lectura: no modifica nada en Superset. Si agregas un chart nuevo, escribe su descripción en las constantes DESC / DESC_OVR / NOTA de scripts/calculos_render.js y vuelve a ejecutar. Si cambian los IDs de los dashboards o la URL, están en las constantes de scripts/calculos_fetch.js.

Superset + SQL Server

Guía completa para instalar Apache Superset con SQL Server en Docker, con actualización automática de datos cada hora y consultas instantáneas.

Apache Superset SQL Server 2019 Docker Redis Cache Windows
Arquitectura

Superset y SQL Server corren en la misma red Docker, eliminando la latencia de red y logrando consultas casi instantáneas.

SQL Server productivo (54.244.218.18)
    ↑ Linked Server (AMECO_DEV)
SQL Server Docker (sqlserver:1433)
    → Job cada 1 hora: TRUNCATE + INSERT
    → Tabla: AmecoHubIntegracion.dbo.AmecoDashboards
        ↑ misma red Docker (instantáneo)
Apache Superset (localhost:8088)
⚡
Con Superset y SQL Server en la misma red Docker, las consultas pasan de ~5 segundos a casi instantáneas.
Requisitos
  • Docker Desktop instalado y corriendo (ícono verde)
  • SQL Server Management Studio (SSMS)
  • Acceso al servidor SQL productivo

2 Construir y levantar los servicios
bash
cd C:\superset
docker compose up -d --build

Esperar unos minutos a que descargue todo y construya la imagen.

⚠️
Si reconstruís la imagen con --build, debés volver a ejecutar los comandos del Paso 4.
3 Crear la base de datos y el usuario admin

Ejecutar los 3 comandos uno por uno, esperando a que cada uno termine:

bash
docker compose exec superset superset db upgrade
bash
docker compose exec superset superset fab create-admin --username admin --firstname Admin --lastname Admin --email admin@admin.com --password admin
bash
docker compose exec superset superset init
✅
Una vez completado, Superset estará disponible en http://localhost:8088 con usuario admin y contraseña admin.
4 Configurar SQL Server Docker

Conectarse desde SSMS a localhost,1434 con usuario sa y password AmecoSQL2024!

sql
-- Crear la base de datos
CREATE DATABASE AmecoHubIntegracion;

-- Habilitar consultas distribuidas
EXEC sp_configure 'show advanced options', 1;
RECONFIGURE;
EXEC sp_configure 'Ad Hoc Distributed Queries', 1;
RECONFIGURE;
5 Crear Linked Server al servidor productivo

Desde SSMS conectado a localhost,1434:

sql
EXEC sp_addlinkedserver
    @server = 'AMECO_DEV',
    @srvproduct = '',
    @provider = 'SQLNCLI',
    @datasrc = '54.244.218.18'

EXEC sp_addlinkedsrvlogin
    @rmtsrvname = 'AMECO_DEV',
    @useself = 'FALSE',
    @rmtuser = 'sa',
    @rmtpassword = 'TuPasswordAqui'

Verificar que funciona:

sql
SELECT * FROM OPENQUERY(AMECO_DEV, 'SELECT @@SERVERNAME')
ℹ️
Si devuelve el nombre del servidor productivo, el Linked Server está funcionando correctamente.
6 Crear Jobs de actualización (cada 1 hora)

Cada job es independiente — si uno falla no afecta a los demás. Todos se crean en SSMS conectado a localhost,1434 desde Agente SQL Server → Jobs → Nuevo Job, programados diariamente cada 1 hora entre 00:00:00 y 23:59:59.

Clonar un Dashboard para otro cliente

Procedimiento para duplicar un dashboard existente (ej. Ameco) y reasignarlo a otro cliente (ej. Centinela), reutilizando datasets que ya existen en Superset.

Prerrequisitos

  • Las tablas destino deben existir en SQL Server (ej. CentinelaDashboards, v_OrdenesTrabajoCentinela) y estar pobladas.
  • Los datasets destino deben estar creados en Superset apuntando a esas tablas.
  • Anotar en qué conexión de BD están los datasets destino (puede ser distinta a la del dashboard original).

Paso 1 — Exportar el dashboard original

En Superset → Dashboards → click en ... del dashboard → Export. Se descarga un ZIP.

Paso 2 — Descomprimir y editar

Descomprimir el ZIP. La estructura interna es:

estructura del ZIP
nombre_export/
  metadata.yaml
  dashboards/NOMBRE-DASHBOARD_1.yaml
  databases/NOMBRE-BD.yaml
  datasets/NOMBRE-BD/NombreDataset_1.yaml
  charts/NombreChart_1.yaml
  charts/NombreChart_2.yaml
  ...

Paso 3 — Reemplazos en el contenido YAML

En todos los archivos .yaml:

  1. Nombres de charts y dashboard: reemplazar el prefijo del cliente (ej. [Ameco] → [Centinela], DEV-AMECO-... → DEV-CENTINELA-...).
  2. Nombres de datasets: reemplazar las referencias (ej. AmecoDashboards → CentinelaDashboards, v_OrdenesTrabajo → v_OrdenesTrabajoCentinela).
  3. UUIDs de charts y dashboard: generar UUIDs nuevos para que no sobreescriban los originales. Cada UUID que aparezca en los YAML de charts y dashboard debe ser reemplazado por uno nuevo (se puede hacer con un script de find & replace global).
🚨
NO reemplazar los UUIDs de datasets ni de la base de datos. Estos deben coincidir con los que ya existen en Superset para que se reutilicen en vez de crear nuevos.

Paso 4 — Obtener los UUIDs reales de Superset

Consultar la API de Superset para obtener los UUIDs de los datasets y la BD destino:

bash — obtener token
TOKEN=$(docker exec superset-superset-1 bash -c 'curl -s -X POST \
  http://localhost:8088/api/v1/security/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"admin\",\"provider\":\"db\"}" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)[\"access_token\"])"')
bash — obtener UUIDs de databases
docker exec superset-superset-1 bash -c \
  "curl -s http://localhost:8088/api/v1/database/ -H 'Authorization: Bearer $TOKEN'" \
  | python3 -c "
import sys, json
for d in json.load(sys.stdin).get('result', []):
    print(f\"{d['database_name']} | uuid={d.get('uuid','?')} | id={d['id']}\")"
bash — obtener UUIDs de datasets (filtrar por nombre)
docker exec superset-superset-1 bash -c \
  "curl -s 'http://localhost:8088/api/v1/dataset/?q=(filters:!((col:table_name,opr:ct,value:Centinela)))' \
  -H 'Authorization: Bearer $TOKEN'" \
  | python3 -c "
import sys, json
for d in json.load(sys.stdin).get('result', []):
    print(f\"{d['table_name']} | uuid={d.get('uuid','?')} | db={d['database']['database_name']}\")"

Paso 5 — Ajustar los UUIDs en el export

En los archivos YAML del export, reemplazar:

ArchivoCampoValor

Paso 6 — Crear el ZIP correctamente

🚨
Superset corre en Linux. El ZIP debe tener forward slashes (/) en las rutas internas, no backslashes. Si se crea desde Windows con PowerShell, las rutas quedan con \ y el import falla silenciosamente. La forma segura es crear el ZIP dentro del contenedor Docker.
bash — crear ZIP dentro del contenedor
# Copiar la carpeta editada al contenedor
docker cp carpeta_export superset-superset-1:/tmp/carpeta_export

# Crear ZIP con Python (garantiza forward slashes)
docker exec superset-superset-1 python3 -c "
import zipfile, os
with zipfile.ZipFile('/tmp/dashboard_import.zip', 'w', zipfile.ZIP_DEFLATED) as zf:
    for root, dirs, files in os.walk('/tmp/carpeta_export'):
        for f in files:
            filepath = os.path.join(root, f)
            arcname = 'carpeta_export/' + os.path.relpath(filepath, '/tmp/carpeta_export')
            zf.write(filepath, arcname)
"

# Copiar el ZIP de vuelta
docker cp superset-superset-1:/tmp/dashboard_import.zip ./dashboard_import.zip

Paso 7 — Importar en Superset

  1. Ir a Settings (ruedita) → Import Dashboard (NO Import Dataset).
  2. Seleccionar el ZIP generado.
  3. Marcar el checkbox "Overwrite" para que actualice los datasets existentes.
  4. Si pide contraseña de la BD, ingresar la del usuario sa.

# Build imagen de produccion
docker build -f Dockerfile.prod -t acrsuper1284.azurecr.io/superset-mssql:latest .

# Push al registry
docker push acrsuper1284.azurecr.io/superset-mssql:latest

Paso 4 — Reiniciar contenedor

El reinicio del contenedor debe hacerse manualmente desde Azure Portal:

  • Ir a superset-app > Reiniciar
  • Esperar a que el estado sea Running
  • Ir a pestaña Conectar > /bin/bash > Connect
  • Ejecutar: superset db upgrade && superset init
